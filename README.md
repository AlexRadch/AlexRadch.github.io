# AlexRadch.github.io

Личный сайт-витрина: небольшие исследования, обзоры сайтов и сервисов,
инструкции. Русский язык.

Собрано на [Hugo](https://gohugo.io) + тема
[hugo-book v0.15.0](https://github.com/alex-shpak/hugo-book)
(субмодуль `themes/hugo-book`, исходники темы не трогаем — только
переопределения в `layouts/` и дополнения в `assets/`).

Публикация: GitHub Actions (`.github/workflows/hugo.yml`) →
https://alexradch.github.io/

## Структура

- `content/_index.md` — главная (список разделов через `section-tree`)
- `content/gists/` — «Фрагменты»: одиночные статьи (`layout: gist`,
  без бокового меню) и многостраничные «книги» со своим меню
- `layouts/` — наши переопределения темы:
  - `baseof.html` — каркас (топбар, крошки, подвал)
  - `landing.html` — главная (подвал включён, теминый его гасит)
  - `gist.html` — одиночный фрагмент без меню
  - `_partials/docs/menu-filetree.html` — левое меню: один каталог
    со своим деревом (рекурсия, глубина `bookSectionDepth`,
    лимит `bookSectionLimit`)
  - `_partials/docs/menu-section.html` — какой каталог рисовать
    (`bookSection` из front matter)
  - `_partials/docs/breadcrumbs.html` — хлебные крошки (логика как
    у темы в main-ветке, корень — `bookBreadcrumbRoot: true`)
  - `_partials/docs/links/edit.html` — «Edit this page» (починена
    под Windows через `path.Clean`)
  - `_partials/docs/prev-next.html`, `opengraph.html` — мелкие правки
  - `shortcodes/section-tree.html` — список страниц раздела
    (`depth`, `summary`, лимит `bookListLimit`)
- `assets/icons/` — свои иконки (в т.ч. `scroll-text` для «Фрагментов»,
  `chevron-right` для крошек — их нет в v0.15.0)
- `assets/styles/custom.css`, `assets/scripts/` — стили и скрипты
- `hugo.toml` — конфиг (язык `ru`, локаль `ru-ru`, параметры `book*`)

## Параметры разделов (front matter `_index.md`)

| Параметр | Чей | Что делает |
|---|---|---|
| `bookSection` | наш | какое меню рисовать (`.` = текущий каталог) |
| `bookBreadcrumbRoot` | наш | корень хлебных крошек |
| `bookSectionDepth` | наш | глубина меню (нет = бесконечно) |
| `bookSectionLimit` | наш | пунктов в меню (нет = без лимита) |
| `bookListLimit` | наш | пунктов в списке `section-tree` |
| `bookFlatSection` | тема | жирный заголовок + дети вровень |
| `bookIcon` | тема | иконка раздела из `assets/icons/` |
| `bookCollapseSection` | тема | книга-аккордеон (CSS, без JS) |

## Дата страницы — обязательно

В шапке каждой страницы фрагмента ставим `date` со смещением пояса:

```yaml
date: 2026-11-23T21:13:37+07:00
```

Список «Фрагментов» сортируется по-хуговски: вес → дата → заголовок,
свежие сверху. У страницы без `date` дата нулевая, и она уезжает в самый
низ списка — со стороны кажется, что новая страница не добавилась.

## Имена ключей (camelCase)

Все свои ключи пишем верблюдом с маленькой буквы (camelCase),
как у темы (`BookSection`, `BookToC`): `minWidth`, `minHeight`,
`coverZoom`, `coverInk`, `fontLinks`, `storybook`. Так везде: каскады
индексников, шапки страниц. В `hugo.toml` своих разделов не держим —
общее по умолчанию живёт в коде шаблона.

Почему: Хуго складывает все ключи в нижний регистр и находит их
любым регистром — верблюд читается и через точку, и через `.Param`.
Дефисы (`min-width`) через точку не читаются вообще, только строкой
через `index`. Змею (`min_width`) ни у нас, ни у темы нет — не заводим.

Кто берёт личное-или-общее: один вызов `.Param "имя"` идёт по цепочке
шапка страницы → каскады предков → конфиг сайта. Отдельно читать
шапку и конфиг не надо.

## Только плоские ключи (засада Хуго)

Все свои ключи — плоские, без домиков. Хуго каскад не клеит:
если внизу у страницы уже есть поле `story`, верхнее `story`
из индексника не спускается вообще — целиком, хоть внутри
ключи разные. Официально:
https://gohugo.io/configuration/cascade/ —
«Hugo does not cascade a value if the descendant already defines
the field». Глубокое склеивание (`_merge: deep`) для каскада
из индексника — только предложение, не сделано.

Поэтому: `coverImage`, `coverZoom`, `coverInk`, `storyTitle`,
`storyUiChapter`... — каждый своим ключом. Низ перебивает верх
по одному ключу, остальные живут. Домик заводить — значит хоронить
весь верх при первом же ключе внизу.

Исключения (списки, их плоскими не сделать): `storyCoverTitle`
(куски `kind/text`), `storyAuthors` (пары `role/name`).
Имена списков тоже верблюдом, внутри — как было.

## Страница: Markdown, шорткоды — только для динамики

Не заворачиваем всю страницу в один шорткод и не рисуем её HTML-ом.
Текст — заголовки, абзацы, ссылки, картинки — живёт в Markdown-файле.
Шорткод нужен только там, где Markdown не справляется: карусель,
интерактив, подключение данных.

Правильно:

```markdown
## Пляж Ао Пхай {#beach}

Текст раздела...

{{< silversand-carousel "beach" "Пляж Ао Пхай" >}}
```

Неправильно: один `{{< page >}}` на всю страницу, внутри которого
HTML-разметка с текстом. Тогда текст нельзя править как текст,
а страница превращается в шаблон.

Картинка-герой — обычный Markdown `![alt](url)`, не шорткод.
Оформление (ширина, высота, отступы) задаётся CSS по месту в странице.

## Стили отдельной страницы

Если странице нужен свой вид, он не размазывается по общему
`custom.css`. В front matter страницы пишем:

```yaml
pageStyle: "silversand"
```

Дальше всё строится от этого слага автоматически:

- `baseof.html` оборачивает контент в `<div class="page-silversand">`;
- `inject/head.html` подключает `assets/styles/page-silversand.css`;
- `inject/body.html` подключает `assets/scripts/page-silversand.js`.

Правило имён: `page-<slug>`, файлы `page-<slug>.css` и `page-<slug>.js`.
Слаг — это имя страницы (`silversand`), а не сокращение.
Никаких `ss-`, `ts-` и прочих ребусов: через месяц по ним не вспомнить,
что это за страница.

Селекторы в файле всё равно начинаются с `.page-<slug>` — стиль
не утечёт, даже если файл случайно подключат ещё где-то.

Классы общих компонентов (например, карусель `.ss-gallery`,
`.ss-slide`) остаются на уровне компонента: это не стиль страницы.

## Переезд страницы — ресурсы едут вместе с ней

Страница меняет слаг (адрес) — её ресурсы переименовываются под новый
слаг в том же заходе:

```sh
git mv assets/styles/page-<было>.css assets/styles/page-<стало>.css
git mv assets/scripts/page-<было>.js  assets/scripts/page-<стало>.js
```

Плюс `pageStyle` в шапке, селекторы в CSS и JS и строки сверки слага
в `layouts/_markup/render-image.html` и `inject/head.html`. Забыть хоть
одно — страница тихо теряет свои стили и шрифты.

Если рядом остаётся жить старая страница (держим до проверки), ей тоже
ставим новый `pageStyle`: файлы-то уже переехали.

Общие кадры (`assets/silversand`) не переименовываем — имена у них одни
на все витрины.

## Удаление страницы — вместе с её ресурсами

Удаляем страницу — убираем и всё, что работало только на неё. Способ —
обратный поиск по репозиторию:

```sh
grep -rn "<имя страницы, шорткода или класса>" . \
  --exclude-dir=.git --exclude-dir=themes --exclude-dir=public --exclude-dir=resources
```

Лишним оказывается: сам файл страницы, `page-<slug>.css` и
`page-<slug>.js`, её шорткоды в `layouts/shortcodes/`, кадры и прочее в
`assets/`, её правила в `custom.css`. Общее не трогаем: классы
компонентов (`.ss-gallery`, `.ss-slide`) нужны всем, кто их использует.

После сборки тот же поиск по `public/`: ноль вхождений на удалённое —
ресурсы вычищены.

Скомпилированное Hugo не убирает: удалённая страница остаётся в `public/`
и кэше `resources/_gen`, и её адрес продолжает открываться. Чистим сами:

```sh
rm -rf public resources/_gen && hugo --cleanDestinationDir
```

Поднятый `hugo server` после такой пересборки подхватывает удаление сам —
перезапускать его не надо.

## Локальная сборка

```sh
hugo server --bind 0.0.0.0 --port 1313 --disableFastRender --navigateToChanged
```

Открыть http://localhost:1313/ (обновлять через Ctrl+F5 — сервер
на грязной сборке иногда отдаёт старое).
