# AlexRadch.github.io

Личный сайт-витрина: небольшие исследования, обзоры сайтов и сервисов,
инструкции. Русский язык.

## На чём

[Eleventy](https://www.11ty.dev/) + стартер
[Eleventy LibDoc](https://github.com/ita-design-system/eleventy-libdoc):
меню по разделам, крошки, поиск, оглавление, светлая/тёмная тема,
печатная версия. Свой CSS и ванильный JS.

Публикация: GitHub Actions → GitHub Pages, https://alexradch.github.io/.
Workflow: `.github/workflows/eleventy.yml`, сборка из `_site`.

## Команды

```sh
npm install      # один раз
npm start        # сервер http://localhost:8080 с автообновлением
npm run watch    # только следить за файлами, без сервера
npm run build    # сборка в _site
```

`npm run` показывает все доступные команды.

## Правила

- Текст — в Markdown. Шорткоды только там, где Markdown не справляется:
  карусель, интерактив, данные. Не оборачивать всю страницу в один шорткод.
  Картинка-герой — обычный `![alt](url)`, оформление — в CSS страницы.
- Свои стили страницы — в отдельном файле по имени слага `page-<slug>.css`,
  селекторы начинаются с `.page-<slug>`, чтобы стиль не утекал. Подключаются
  полем `pageStyle` во front matter; рядом так же лежит `page-<slug>.js`.
- Удаляешь страницу — забираешь её ресурсы; общие классы компонентов не трогаем.
  Ищи обратно по имени страницы, слага, шорткода и класса по репозиторию
  (кроме `.git`, `node_modules`, `_site`), а после сборки проверь, что в `_site`
  упоминаний не осталось.
- Меняешь слаг страницы — в том же заходе переименуй `page-<slug>.css` и
  `page-<slug>.js`, поправь `pageStyle` в шапке и селекторы в этих файлах.
  Забыть хоть одно — страница тихо теряет свои стили.
- Имена своих ключей — camelCase; короткие ребусы (`ss-`, `ts-`) не заводим.
- Свои расширения Eleventy лежат отдельно в `lib/gist-extras.js`. В `.eleventy.js`
  только импорт и подключение плагина — файлы LibDoc при обновлении не переписываем.
- Порядок в меню и списках задают `sortValues` и `comparePages` в `lib/gist-extras.js`:
  сначала `order` по возрастанию (нет = 0), потом дата по убыванию. Новые поля
  добавляются в эти две функции.
- Глубина меню, раскрытая по умолчанию, — `navExpandedDepth` в `settings.json`
  (1 — только разделы, 2 — разделы и их дети, глубже — свёрнуто). Исключение
  для узла — `navChildrenExpanded: true|false` в шапке его страницы: поле
  задаёт состояние списка его потомков. Ветка текущей страницы раскрывается
  всегда, а в режиме `?nojs` видно всё дерево.  Состояние и кнопки +/− печатаются в HTML при сборке: меню не меняет вид
  после загрузки и не запоминает выбор посетителя. Переключает только кнопка;
  клик по названию ведёт на страницу.
- Оглавление на странице и плавающее оглавление справа показывают сначала
  главы, потом подстраницы текущей страницы — их отделяет тонкая линия и
  подпись «Страницы» из `libdocMessages.pages`. На страницах-указателях,
  где детей много и они уже выведены списком, ставь `tocPages: false` в шапке.
- Состояние локального «Оглавления» (`#toc_main`) запоминается на весь сайт
  в `localStorage`: `tocMainExpanded` в объекте `eleventyLibdoc`. Если
  значения нет, оглавление открыто, как в разметке. В `?nojs` состояние
  не сохраняется и оглавление всегда открыто.
- В шапке фрагмента указывай `date` с поясом, например
  `2026-11-26T14:12:00+07:00`: списки и меню сортируются по убыванию даты.
  Без явной даты Eleventy берёт дату файла — порядок меняется при переносе.
- Превью страницы в соцсетях и мессенджерах — `ogImageUrl` в шапке, полная
  ссылка на картинку 1200×630. Без него берётся общая картинка из
  `settings.json`; оставлять картинку темы по умолчанию нельзя. Файл обложки
  фрагмента называй `og-gist-<slug>.png`, по имени страницы.
- Список страниц любой секции — `{% pageList "Фрагменты" %}` или
  `{% pageList "Фрагменты" 5 %}`; возвращает только `<ul>`, заголовок пишем
  в Markdown рядом. Функции в `lib/gist-extras.js` экспортируются и доступны
  не только как shortcode, но и из другого кода.
- Язык сайта — `ru` в `settings.json`. `language: en` в front matter отдельной
  страницы переключает `<html lang>` и подписи интерфейса на этой странице.
  Без поля страница остаётся русской.

## Заметки по CSS (решения и идеи)

- Вид задаёт LibDoc как он есть; чужие шаблоны не смешиваем.
- Больших CSS-фреймворков (Tailwind, Bootstrap и т.п.) не берём: для простой
  правки приходится писать слишком много обвязки. Свой CSS на переменных —
  достаточно.
- Если понадобится структура CSS — слои `@layer` в порядке:
  reset → fonts → variables → global → compositions → blocks → utilities.
  Идея подсмотрена в eleventy-excellent; там Tailwind работает как генератор
  переменных, но нам он не нужен.
- Сброс свойств: короткий свой reset по идеям Josh Comeau
  (https://www.joshwcomeau.com/css/custom-css-reset/) — без npm-пакета,
  лежит в проекте и меняется вместе с ним; кладём в `@layer reset`.
  Полезные правила: `overflow-wrap`, `text-wrap: pretty/balance`,
  `max-width: 100%` у медиа, наследование шрифта в формах.
- JuicyDocs не берём: для нашей задачи он проще по навигации и оформлению.
